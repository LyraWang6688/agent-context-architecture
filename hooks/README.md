# hooks/ · Hook

> **内部结构待定。**王颖说这一层"先建文件夹，但还没想好怎么做"。
> 所以本文件**只写定义**，不预设切法。

## 这部分是什么

**什么必须自动发生。**

## 回答什么问题

> 「什么事情必须自动发生，或被强制？」

## 为什么它要独立成文件夹

**因为它的动作和其他部分不同：**

| | 动作 |
|---|---|
| `preferences` / `memory` / `global` / `integrations` | **要我记住**（读一次，理解） |
| **`hooks/`** | **要我做 / 要系统拦**（触发即执行） |

混进"要读的知识"里，Hook 会被当成背景读过去——
**而 Hook 的全部价值恰恰在于它不被略过。**

## 收什么

- **有触发点**的内容：能说清"什么时候"
- **可判定**的内容：能做 / 不能做，无歧义
- **有失败语义**的内容：做不到时是阻断，还是警告

## 不收什么

- ❌ 建议、偏好 —— 没有触发点就不是 Hook
- ❌ 需要解释才能判断的内容 —— 不可判定就不能自动执行
- ❌ 随时都该遵守的状态 —— 那是 `global`

## 准入判据（三条全中才算）

1. **有触发点**——能说清"什么时候"
2. **可判定**——能做 / 不能做，无歧义
3. **有失败语义**——做不到时是阻断，还是警告

不满足的，退回 `global` 或 `preferences`。

## 强制力必须标注（这一层最重要的规矩）

**文档里的 Hook 不会自动执行。**所以每条必须标清：

| 标记 | 含义 | agent 该怎么做 |
|---|---|---|
| `ENFORCED` | 在某个真实宿主里已安装、**真的会拦** | 可以依赖 |
| `DECLARED` | **只声明，靠自觉** | **不要以为自己被保护了** |

> **标 `DECLARED` 的就不是 Hook，是约定。**
> 不标清楚，agent 会以为自己被保护了——**这是最危险的一种误解。**

## 内部结构

**一个 Hook 一个文件**，文件名 `HA-NN-<slug>.md`（NN 两位数，便于排序）。

每个文件必须包含：

```
触发点 / 必须发生 / 判据 / 失败处理 / 强制力
```

## 现有 Hook

| **HA-01** | 任务完成 / 交接 / 被问「干净了吗」 | `DECLARED` | [`HA-01-wrapup.md`](HA-01-wrapup.md) |

> **目前全部是 `DECLARED`。**
> 真的会被系统拦的规则，不在这个目录——
> 它们在 `integrations/`（如 GitHub 的 `delete_branch_on_merge`）和 git 配置里。
> **这个目录记录的是"系统管不了、只能靠约定"的那部分。**

## 为什么这里会有 DECLARED

因为**有些事永远无法被系统强制**：

```
能强制的   →  去 integrations/ 找平台机制，或写 git hook / CI
不能强制的 →  留在本目录，标 DECLARED，让下一个 agent 至少知道有这回事
```

**标 DECLARED 不是失败，是诚实。**不标才危险。
